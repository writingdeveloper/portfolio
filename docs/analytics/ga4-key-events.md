# GA4 핵심 이벤트 (전환) 설정

작성: 2026-08-04

## 왜 0이었나

사이트는 `gtag('config', …)`만 호출하고 있었다. 즉 **페이지뷰만** 보냈고 커스텀
이벤트가 하나도 없었으므로, GA4 콘솔에서 핵심 이벤트로 지정할 대상 자체가 존재하지
않았다. 개선을 아무리 해도 효과를 잴 수 없는 상태였다.

## 무엇을 세는가

포트폴리오에서 의미 있는 전환은 전부 **떠나는 순간**이다. 데모를 열었거나, 코드를
보러 갔거나, 스토어로 갔거나, 메일을 열었다면 사이트가 제 일을 한 것이다.

| 이벤트 | 발화 조건 |
|---|---|
| `demo_click` | 외부 호스트로 나가는 링크 (제품 데모·라이브 사이트) |
| `code_click` | github.com · gitlab.com · bitbucket.org |
| `play_store_click` | play.google.com |
| `contact_click` | `mailto:` |

각 이벤트는 `link_url`과 `link_domain` 파라미터를 함께 보낸다. 데모마다 URL이
다르므로 `link_url` 분해만으로 **어느 프로젝트가 열렸는지**까지 볼 수 있다.

## 구현

- `src/lib/analytics.ts` — 순수 분류 함수. DOM도 gtag도 모르므로 그대로 테스트된다.
- `src/components/analytics/OutboundTracker.tsx` — document에 캡처 단계 클릭
  리스너 하나. 프로젝트 카드·홈·묘비·푸터·MDX 본문의 링크를 전부 덮는다.

카드마다 `onClick`을 붙이면 서버 컴포넌트들이 전부 클라이언트 컴포넌트가 되어
계측값보다 훨씬 많은 JS를 싣게 되므로, 위임 리스너 하나로 처리했다. 글 본문 안의
링크까지 덮이는 것은 컴포넌트별 접근으로는 못 얻는 이득이다.

캡처 단계인 이유는 앵커가 곧 페이지를 떠나기 때문이다. 버블 단계 리스너는 같은 탭
이동에서 경합에 질 수 있다.

## 남은 수동 작업 (콘솔)

**코드만으로는 끝나지 않는다.** 이벤트를 "핵심 이벤트"로 표시하는 것은 GA4 콘솔에서만
가능하다.

1. GA4 (속성 `G-77H1KB1H05`, 계정 sihyeongdev@gmail.com) → **관리 → 데이터 표시 →
   이벤트**
2. 배포 후 실제 클릭이 한 번씩 발생하면 목록에 `demo_click`·`code_click`·
   `play_store_click`·`contact_click`이 나타난다. 각 행의 **핵심 이벤트로 표시**
   토글을 켠다.
3. 데이터가 도착하기 전에 미리 만들려면 **관리 → 핵심 이벤트 → 새 핵심 이벤트**에서
   위 이름을 그대로 입력해도 된다. 이름은 정확히 일치해야 한다.

이벤트 이름은 한번 데이터가 쌓이면 바꾸지 말 것. 콘솔 설정이 이름에 묶여 있다.

## 참고

GA4 향상된 측정의 `click`(outbound) 이벤트와는 별개로 동작한다. 향상된 측정은 모든
외부 클릭을 이름 없는 `click` 하나로 합치므로, "스토어로 갔다"와 "코드를 보러 갔다"를
구분해 전환으로 세려면 위처럼 이름 있는 이벤트가 필요하다.
